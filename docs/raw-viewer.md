# 原始数据查看器（平台 0.5.0）

入口为顶部“原始数据”或 `http://marvin-thor.local:8095/#raw`。这是对服务器已保存录制的只读浏览，不是 LeRobot 转换，也不需要先让 provider check 通过。格式针对已核验的 Thor/Tianji 数采目录：`data/metadata.yaml` 及其 MCAP，`video/**/metadata.yaml` 及其四宫格 H.264 MCAP。正在录制/尚未关闭的 session 会被拒绝，避免读取不断变化的半成品。

## 操作

1. 输入或通过“选择目录”浏览服务器上的单条录制/父目录。输入时可按路径前缀补全；点“加载录制”，按名称筛选，再选择一条“打开原始数据”。首次打开会显示索引进度，之后按源文件指纹复用预览。
2. 左侧勾选任意 topic，展开“选择字段”决定绘图分量，例如 JointState 的 position/velocity/effort，wrench 的 force/torque，夹爪反馈的原始 data 数组。最多同时查看 12 个 topic、每图 16 个字段。“常用信号”恢复关节与左右 wrench，“全不选”清空。空 topic 仍显示，字符串/状态 topic 通过原始消息面板查看。
3. 点击“播放/暂停”、选择 0.25/0.5/1/2 倍速，或拖动播放条/输入秒数跳转。“上一帧/下一帧”按真实视频帧时间定位，不假设 50 FPS。点击任意曲线也会跳转，图表聚焦后可用左右方向键微调 20 ms。
4. 四个相机窗口依次是头部左/右、左腕/右腕，均从同一个浏览器解码帧裁出，所以不会出现四个独立播放器之间的漂移。各窗口可放大全屏。原始四宫格没有重新压缩，只把 H.264 包按原时间戳封装成 MP4；原始单路像素尺寸不变。
5. 所有图表横轴范围一致，红色细竖线是当前播放时刻。“放大/缩小”围绕游标调整可视区间，“全程”恢复完整录制。播放器在宽屏下与曲线并排，滚动时保留在视野内；窄屏改成纵向排列。切换标签页或浏览器进入后台会暂停。
6. 每个 topic 下方显示游标之前最近一条真实消息、消息时间和距游标的毫秒数。展开可读完整的结构化消息预览，包括 header/frame_id/name 等。它是原始消息查询，不是对齐后的 DatasetSource 行；缺口中显示旧消息会明确显示时间差，超过 topic 末尾也会标明。

## 两种时间基准

默认 **MCAP 记录时间**，把所有消息的 `log_time` 映射到同一条接收时间轴。横轴零点是所选时钟下整条录制最早的可读取消息，秒数通过整数纳秒相减再转换，避免把 Unix 纳秒时间直接放进 JavaScript 浮点数。范围取全部信号的覆盖并集，不采用转换时的交集，因此能直接看出“视频先开始或后结束”。

**Header 时间**优先用 `header.stamp`；无 Header 或 Header 无效时用该消息的 MCAP 时间。两种时间基准均保持真实时间间隔，不将每个 topic 各自平移到 0。界面列出 Header 有效消息数及 `Header − MCAP` 偏差范围；超过 1 秒的偏差会提示。没有自动校正设备时钟或网络延迟，也不宣称不同来源时钟天然同步。四宫格共用合成帧时间戳不等于各相机曝光硬件同步。

每 topic 展示的 Hz 是正采样间隔中位数的倒数，属于典型采样频率，不是消息总数/时长的平均吞吐。最大间隔、重复和回退也保留在预览元数据中。绘图按所选时间稳定排序；发现回退时明确提示，原始消息不修改。Header 视频时间重复/回退时不给出误导性 MP4，可改用 MCAP 时间；数值 topic 仍可浏览。

## 原始数值和缺口

预览不执行关节重排、夹爪归一化、低通、插值、采样降频、wrench 窗口、控制补 state、首尾静止裁剪，也不把某路缺失当成“保持不动”。原消息单位由 schema/数采系统决定，数组顺序与原文件一致；例如 `position[i]` 对应同条消息 `name[i]`。

曲线只连接相邻真实点；原采样间隔超过 `max(100 ms, 5 × 正间隔中位数)` 时断开，这是可视化规则，不是 provider 转换验收阈值。NaN/Inf 或缺失字段也断开。缩小时按桶选择真实 min/max 极值及边界，既不平均也不插值；缺口标志来自完整原始采样，不把绘图抽点间距误报成观测缺口。放大后可查看更细的点，游标消息查询始终来自完整消息索引。

视频按实际时间播放，内部缺口保留；超过上一帧 100 ms 时显示“暂无新视频帧”，而不是声称有新观测。超出视频覆盖时遮罩提示，数值时间轴可以继续播放。源视频结构/解码不可靠时只禁用视频并显示错误，已读取的数值和文本仍可检查。

## 缓存、资源和限制

- 原文件不写入，预览文件单独放在 `.state/raw-viewer/<指纹>/`，包括 NPZ 数值、SQLite 消息、MP4 和完成清单。临时原始 H.264 抽取文件封装结束后删除。没有创建 LeRobot 数据集或新增“数据集”登记。
- 一次只启动一个低优先级索引进程，队列最多 4 条；同一指纹的重复打开合并。索引完成后重启可复用；中断的目录保留到唯一诊断目录再重建。每次读数据或视频仍核对源文件身份/元数据指纹，变化后要求重新打开。指纹不是内容哈希或源文件锁。
- 每条最多 128 个 MCAP、200 万消息、2000 万数值，索引最多 10 分钟。超限明确失败，不静默截断轨迹。数值字段最多 256；原始消息预览的长数组最多前 256 项、字符串最多 65536 字符、嵌套最多 8 层，截断在文本中标明。极端多缺口的图表会要求放大。
- 当前只播放标准 ROS2 CompressedImage 中的四宫格 H.264、无 B 帧的已核验录制布局；不猜测其他相机 topic 的拼接规则。非 CDR/未知 schema/解码失败在对应 topic 中报告。
- 预览缓存不会自动清除。管理员可在无预览索引任务时按需清理专属 `.state/raw-viewer` 缓存；原始录制与转换结果不受影响。服务仍为原有可信网络访问模型，不新增全局工具或认证方式。

## 设计参考与模块

参考已部署 LeTools 的 `lerobot-dataset-visualizer`：`context/time-context.tsx` 的共享时间、`simple-videos-player.tsx` 的 seek 与播放区别，以及 `data-recharts.tsx` 的时间轴点击和 ReferenceLine。原始 MCAP 的 schema、两种时间戳和稀疏 topic 与 LeRobot 表不同，因此实现独立适配层，不修改上游或 provider。

`raw_data.py` 负责安全源快照、原始 schema 解码/字段索引、无损视频封装和点查询；仅复用已安装 provider 的 schema 编译器。`raw_worker.py` 在私有解释器中建立完成清单。`raw_viewer.py` 管理有界任务、缓存生命周期和路径受限 API。`raw.js` 使用单个共享时间状态、一个视频解码器和四个 canvas，SVG 图表竖线只更新 x 坐标；`raw-timeline.js` 中的纯时间逻辑有独立测试。
